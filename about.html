About Foundry IQ Demo Studio

Why this demo exists

Foundry IQ and Azure AI Search offer many retrieval techniques: keyword, vector, hybrid, semantic ranking, scoring profiles, agentic retrieval, multimodal search and more. They are easy to describe and hard to feel. This studio puts each technique side by side as a BEFORE and AFTER comparison on the same synthetic Zava Retail corpus, the same query and the same evidence budget. You see real ranked documents and citations, not marketing claims.

How it helps

  • Shows what changes, and what does not, when you switch on a retrieval feature.
  • Every result links to its source document, page or table row, so claims can be checked.
  • Technical details show the exact index, filters, API version, request IDs and timing for each arm.
  • Five document languages show language-specific analyzers and multilingual vectors.
  • Failures are shown as failures; the app never invents passages, citations or timings.

Sample mode vs Live data

Live data sends real queries from the server to Azure AI Search. Query vectors are computed by the index vectorizers inside Azure AI Search. Your browser never sees a key.

Sample mode replays real Live responses that were recorded for every curated example, in all five languages, with the capture date shown. It sends no Azure request. Sample is always labeled and is never used as a silent fallback when Live fails.

Open Advanced options under the search box to switch mode and evidence count.

The scenarios

S01 Keyword search Live

Plain app-style substring matching vs Azure full-text search with language analyzers and synonym maps.

Why it matters: “drill” should find a “hammer drill”, and typed product names should still match.

S02 Vector search Live

Keyword (BM25) ranking vs vector similarity from the index’s text-embedding-3-small vectorizer.

Why it matters: describe the need (“a light tool for holes in brick”) instead of guessing product words. Exact IDs can still favor keyword.

S03 Hybrid search Live

Keyword vs hybrid (keyword + vector with reciprocal rank fusion) under identical category and price filters.

Why it matters: hybrid keeps exact matches and adds meaning, while filters still apply.

S04 Semantic reranking Live

The same hybrid candidates before and after the Azure semantic ranker.

Why it matters: shows rank movement only. No new documents appear, so the effect is easy to attribute.

S05 Retail search Live

Location, stock, category and price filters, with keyword vs hybrid results plus category facets.

Why it matters: commerce search needs hard eligibility rules and navigation, not just relevance.

S06 Document boosting Live

The same hybrid query with and without a reviewed scoring profile: freshness, magnitude, distance, tags or availability.

Why it matters: business signals can reorder relevant results in an explainable way.

S07 Agentic search Live Evidence only

Single-pass hybrid retrieval vs native single-index agentic retrieval on the same support index, with a bounded runtime.

Why it matters: a complex support question needs policy, warranty and manual evidence together. This deployment compares retrieved documents and citations; it does not generate answers.

S08 Agentic + graph search Live Custom

Search evidence vs the same evidence plus an Azure-indexed, custom bill-of-materials graph.

Why it matters: tracing a supplier defect to affected lots and models needs relationships. This is a custom projection, not native graph support.

S09 Topics + entries Live Experimental

Search evidence vs an experimental, versioned topic projection that expands to its sources.

Why it matters: recurring issues are easier to explore as topics, as long as each topic stays grounded in sources.

S10 Content Understanding Live Pre-ingested

Azure Content Understanding Read pages vs Layout table rows from the same PDF. Extraction ran at ingestion; queries run live.

Why it matters: table-aware extraction cites the exact page and row (for example, a model’s drilling diameter).

S11 Multimodal image search Live Preview

Keyword search over image metadata vs Azure Vision multimodal vectors computed by Azure AI Search, from an uploaded image or a text description.

Why it matters: shoppers often have a picture, not the right words. Uploads are bounded to 40 KiB and never stored.

Five document languages

Each language has its own translated corpus and indexes, with language-specific analyzers. English is never substituted for another language.

  • English
  • Français
  • Español
  • 日本語
  • Deutsch

Change the language from the profile menu: Settings › Document language.

Current limitations

  • All content is synthetic (Zava Retail); no customer data.
  • S07 compares retrieval evidence only; it relies on paid Standard knowledge retrieval and has no generated answers here.
  • S08 is a custom graph projection and S09 is experimental; neither is a native feature.
  • S10 uses PDFs processed by Content Understanding at ingestion; new PDF uploads are not supported.
  • S11 uses a preview vectorizer; uploads are limited to 40 KiB JPEG, PNG or WebP.
  • Requests are rate limited. The first Live query after a quiet period can take longer while Azure warms up.
